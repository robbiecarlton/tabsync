# Build Plan

Companion to `SPEC.md`. Records the build order and decisions that refine or deviate from the spec.

## Decisions (2026-10-22)

| #   | Topic                   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Migrations              | drizzle-kit generates `up` SQL from the schema; each migration gets a hand-written `down.sql`. A small custom migrator (`up` / `down` / `status`) runs against both PGlite and `pg`. A test applies up → down → up.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| D2  | Pre-restore snapshots   | Uploaded (so undo is in shared history) but `GET /v1/snapshots/latest` ignores `kind = 'pre-restore'`. After applying another device's snapshot, base = that snapshot and nothing is pushed. After a history restore, the resulting state is pushed as a new `manual` snapshot so other devices see Behind.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| D3  | Ordering                | Add server-set `received_at timestamptz not null default now()` to `snapshots`; "latest" is ordered by `received_at`. Client `createdAt` remains the AAD, display time and retention key. Index `(profile_id, received_at desc)` added.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| D4  | Join                    | "Join with a secret" never registers. It derives credentials and checks the server; an unknown profile gives "No sync profile found for this secret" and nothing is written locally. Only "Create new profile" calls `POST /v1/profiles`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| D5  | History device names    | Device names are encrypted, so the popup fetches and decrypts the (≤ 8) snapshots the labels resolve to, cached by snapshot ID.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| D6  | Retention horizon       | Weekly slots extend to 1 year + 1 week (not exactly 1 year), otherwise the "1 year ago" label could almost never resolve. Known effect of the spec's tiering: at a tier boundary the first minutes after an idle gap can be pruned in favour of a newer snapshot in the same slot, so a label may land just before the gap (e.g. Friday evening rather than Monday 09:10). Lost activity is always within one slot.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| D7  | Blob layout             | `version byte (1) + 12-byte IV + AES-GCM ciphertext` (spec: IV + ciphertext). The version byte allows algorithm changes later. Plaintext is always gzipped. AAD is `tabsync/v1\|<profileId>\|<createdAt as epoch ms>`, so it survives the server re-serializing timestamps; decrypt also checks the snapshot ID matches the server record.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| D8  | Auth header             | `Authorization: Bearer <profileId>.<authToken>` (spec: token only). The server looks up the profile by ID, then compares token hashes in constant time; with the token alone there would be nothing to compare. Unknown profile and wrong token both give 401.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| D9  | API wire format         | JSON throughout; blobs are base64url strings. Missing latest snapshot is 404 `no_snapshots`. Uploads more than 10 min in the future are 422 `clock_skew`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| D10 | Empty layouts           | The extension never pushes a layout with zero windows (after exclusions). On macOS closing the last window leaves the browser running, and quitting fires removal events; publishing an empty snapshot would invite the other machine to close everything.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| D11 | Join baseline           | After joining, the device records its current layout fingerprint but no base snapshot, and pushes nothing until its layout changes. With no base, milestone 4 will show the server's latest as Behind and offer Apply. Fresh browser sessions (detected via an empty `chrome.storage.session`) ignore tab events for 10 s, then flush only if the layout differs from the last push.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| D12 | Behind behaviour        | While Behind, pushes are held so this device never overwrites a newer snapshot it hasn't seen applied (milestone 5 turns "Behind + local edits" into the conflict choice). A newer snapshot whose layout is identical to the local one is adopted silently. Pull triggers: popup open, window focus (≤ 1 per 30 s), the 1-minute alarm, Sync now, and after each push timer.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| D13 | Reconcile details       | Windows pair by tab overlap; leftover target windows reuse blank (New Tab only) windows before creating new ones. "Match exactly" never closes internal pages (settings, extensions…), which are never synced; blank New Tab pages are dropped in both modes. Existing windows keep the user's active tab unless it was closed; new windows activate the snapshot's active tab. Window bounds aren't restored (screens differ between machines); maximized state is (fullscreen isn't: on macOS it opens a separate Space). Chrome rejects creating an unfocused maximized window, so windows are created plain and maximized afterwards. A URL the browser refuses to open is left out (and logged) rather than aborting the apply. Tabs aren't moved between windows: a tab in the "wrong" window is created in the right one (and closed from the other in "match exactly"). New tabs are discarded once their URL commits. After applying, tab events are ignored for 2 s, then the layout is fingerprinted once more. |
| D14 | Conflict detection      | Conflict = Behind (server latest isn't this device's base) **and** local edits (current fingerprint differs from the last pushed/adopted one). Before every push the extension re-checks the server's latest (one cheap If-None-Match request); if another device pushed meanwhile it reports Behind/Conflict instead of overwriting. This closes the gap where a device edits before its next pull, without making the server compare-and-swap.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| D15 | Resolving and restoring | **Keep mine** pushes this layout as a `manual` snapshot whose parent is theirs. **Take theirs** applies theirs in match-exactly mode (undo point first). **Merge** applies theirs in add-missing mode, then pushes the union as `manual`. **Restore** applies the chosen snapshot with the user's mode (undo point first) and pushes the result as `manual` unless it equals the server's latest. History shows one row per label (1 min … 1 year) plus "Undo last apply or restore" (this device's newest pre-restore snapshot).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| D16 | No data: favicons       | Snapshots never store `data:` favicon URLs (spec: drop those over ~2 KB). Inline image data barely compresses (~1.4 KB per tab after gzip), so ~1,500 such tabs would exceed the server's 2 MB request limit, while URLs and titles alone stay far below it even at 10,000 tabs. Favicons are a fallback only; v2 uses the browser's `_favicon` cache.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| D17 | Server URL              | The deployed server `https://tabsync-production.up.railway.app` is the default and is granted in `host_permissions` alongside `http://localhost:8787` for development (set it in options when working locally). Other URLs are granted per origin at runtime.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| D18 | Minimal reconcile       | Applying changes as little as possible: target groups reuse the live group most of their tabs are in (same group ID, so collapsed groups don't flicker open); only tabs whose group membership changes are ungrouped or added; only out-of-place tabs move, and groups move as a unit (`tabGroups.move`); title, colour and collapsed state are set only where they differ. Tests assert the exact browser operations.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| D19 | Favicons                | Shown via the `_favicon` API (`chrome-extension://<id>/_favicon/?pageUrl=…&size=32`), which serves the browser's cached icon. It never fails: for an unvisited page it returns a generic default, so the `Favicon` component compares the loaded pixels with the default (fetched once for a sentinel URL) and then falls back to the snapshot's stored `favIconUrl` (http(s) only), or an empty box.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| D20 | Snapshot browser        | A full extension page (`snapshots.html`), not the popup, since snapshots can hold hundreds of tabs. The list shows every snapshot by day with time, kind and restore-label tags; device names are encrypted, so a snapshot is decrypted when selected (and remembered for the list) rather than all ~170 up front. Clicking a tab focuses it if it's already open in any normal window (exact URL first, then the normalized match, current window preferred), otherwise opens it; cmd/ctrl-click always opens a new background tab; "Open group" reopens the group with its title and colour. Restoring stays in the popup.                                                                                                                                                                                                                                                                                                                                                                                               |
| D21 | Diffs                   | `compareLayouts` (shared) matches tabs as a multiset by URL within paired windows, then across windows (those are window moves). A matched tab is "moved" if it changed window, group, pinned state or relative order. Relative order uses the longest increasing run of positions, so inserting or closing one tab doesn't make later tabs look moved. Groups are paired by shared tabs, so renaming or recolouring a group doesn't move its tabs. In the snapshot browser: compare a snapshot with what's open now or another snapshot (older on the left, swappable); routes `#<a>/vs/<b>` with `now` allowed; the popup's Behind/Conflict cards link to "now vs theirs".                                                                                                                                                                                                                                                                                                                                               |
| D22 | Exclude list            | Per-device list in options (not carried in snapshots). Syntax: `bank.com` / `*.bank.com` = host and subdomains (optional port); `https://…` = URL prefix (scheme/host case-insensitive); `#` comments. A line needs `scheme://` to count as a URL, so `localhost:3000` is a host and port. Excluded URLs are treated like internal pages both ways: never captured, never opened from another device's snapshot, never matched or closed by reconcile; Behind/Conflict summaries and "identical" adoption ignore them. Changing the list marks the layout changed so the next push drops newly excluded tabs. Existing history is not rewritten (snapshots are encrypted and immutable).                                                                                                                                                                                                                                                                                                                                   |

## Tooling

- npm workspaces: `shared/`, `server/`, `extension/` (pnpm not installed; npm workspaces suffice)
- TypeScript, Vitest, ESLint, Prettier
- Server: Hono, Drizzle, PGlite (local/tests), `pg` (Railway)
- Extension: Vite MV3 build, Preact for popup/options
- Each package has its own semver version, `CHANGELOG.md` and `README.md`; the root has a unified `CHANGELOG.md` and `README.md`

## Milestones

Finish and test each before starting the next.

0. **Skeleton.** Workspace, root scripts (`dev`, `test`, `build`, `typecheck`), server with `GET /health` + DB connection + migrator, extension shell (empty worker, popup, options), changelogs and READMEs.
1. **Shared core.** Types + runtime validation, URL normalization/exclusion, fingerprint, multiset + window matching, diff summary, retention (prune + label resolution, simulated-year test), crypto (HKDF, AES-GCM with AAD, gzip, base32 secret).
2. **Server.** Five endpoints, bearer auth (constant-time), 2 MB cap, in-memory rate limits, pruning after insert + daily sweep. Tests on in-memory PGlite via `app.request()`.
3. **Extension capture and push.** Pure logic behind a thin `chrome.*` adapter (mocked in tests). Setup flow, capture, debounce state machine (5 s / 30 s max / alarm flush), startup settle, encrypt + push, badge.
4. **Pull and apply.** Behind detection, Apply with two modes, reconcile as pure planner (current + target → ops) + executor, unloaded tabs, echo suppression, pre-restore.
5. **Conflicts and history.** `parentSnapshotId` conflict detection, conflict UI, history labels + restore.
6. **Deploy.** Railway service + Postgres, migrations on deploy, two-machine checklist (run by the user).
7. **Polish.** Debug log, error messages, retry behaviour.
